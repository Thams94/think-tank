# 部署说明（给站点维护者）

这是一个**纯静态前端**，没有后端、没有数据库、不需要 Node 运行环境。
传上去就能用，所有请求由访问者的浏览器直接发给他们自己填的 API。

---

## 1. 需要上传哪些文件

把**整个目录**传上去即可，但可以排除这些（不影响运行）：

```
node_modules/      ← 开发依赖，运行不需要（产出的库已经放进 vendor/）
tools/             ← 打包/测试脚本
.testfiles/        ← 测试用文件
.edge-profile/     ← 测试用浏览器配置
*.md               ← 说明文档（可选上传）
server.js          ← 仅本地预览用
启动网页版.cmd      ← 仅 Windows 本地用
```

**必须上传**：

```
index.html
style.css
app.js
web-bridge.js
vendor/pdf.min.mjs
vendor/pdf.worker.min.mjs
vendor/mammoth.browser.min.js
```

## 2. 服务器要求

| 项 | 要求 |
|---|---|
| 类型 | 任意静态托管（Nginx / Apache / 宝塔 / Vercel / Netlify / GitHub Pages / OSS+CDN） |
| HTTPS | **必须**。否则浏览器可能拦截，Key 也有被中间人截获的风险 |
| 目录 | 放在网站根目录或任意子目录都行（所有路径都是相对路径） |
| 重写规则 | 不需要（单页，没有路由） |

### 关键：`.mjs` 文件的 MIME 类型

`vendor/pdf.min.mjs` 是 ES Module，服务器必须返回 `text/javascript`。
**很多服务器默认把它当 `text/plain`，会导致 PDF 解析直接失效。**

**Nginx**（在 `http { }` 或 `server { }` 里）：

```nginx
types {
    text/javascript mjs js;
}
```

或者更稳妥地加一条：

```nginx
location ~* \.mjs$ {
    default_type text/javascript;
}
```

**宝塔面板**：网站设置 → 配置文件，加进 `server { }` 块里同样的两行。

**Apache**（`.htaccess`）：

```apache
AddType text/javascript .mjs
```

**Vercel / Netlify / GitHub Pages**：默认已正确，无需配置。

### 建议的完整 Nginx 片段

```nginx
server {
    listen 443 ssl http2;
    server_name your-domain.com;

    ssl_certificate     /path/fullchain.pem;
    ssl_certificate_key /path/privkey.pem;

    root /www/wwwroot/ai-group-chat-web;
    index index.html;

    # 关键：让 .mjs 以 JS 类型返回
    types { text/javascript mjs js; }

    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源缓存（可选）
    location ~* \.(mjs|js|css|png|svg)$ {
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

## 3. 跨域（CORS）——使用中最可能遇到的问题

浏览器会直接从用户电脑请求他们填的中转站地址。**如果该中转站不返回跨域头，请求会被浏览器拦下。**

- 已确认可用的例子：`https://ai.789210.xyz/v1`（返回 `Access-Control-Allow-Origin: *`）
- 不能用的：大部分不带头部的私有部署

界面上会提示：

> 请求被浏览器拦截。常见原因：该中转站不允许网页跨域访问（CORS）……

**这是访问者自己选的供应商的问题，不是站点的问题**，无需处理。
如果希望彻底解决，可以在服务器上加一个转发接口（见第 6 节）。

---

## 4. 安全建议

1. **不要**在代码里写死任何 API Key
2. 建议在站点根目录放一个 `robots.txt`，避免被搜索引擎收录：

```txt
User-agent: *
Disallow: /
```

3. 如果需要限制访问，最简单的做法是在前面加一层 HTTP Basic Auth（Nginx）：

```nginx
auth_basic "restricted";
auth_basic_user_file /etc/nginx/.htpasswd;
```

4. 页面上已有提示：Key 只存在访客自己的浏览器里，站点不收集任何数据。

## 5. 代码结构（方便二次修改）

| 文件 | 作用 | 想改什么来这里 |
|---|---|---|
| `index.html` | 页面骨架 | 加/改控件、文案 |
| `style.css` | 全部样式 | 配色、布局（深色主题，`:root` 里有变量） |
| `app.js` | 界面逻辑：三栏、会话、成员、调度、私密@、渲染 | 交互与调度逻辑 |
| `web-bridge.js` | 浏览器能力：存储、请求、文件解析、搜索、导出 | 换存储方式、换搜索源、加代理 |
| `server.js` | 本地预览服务器（零依赖） | 只在本地用 |

**改配色**：`style.css` 开头的 `:root` 变量。
**改搜索源**：`web-bridge.js` 里的 `webSearch()`。
**加代理**：在 `web-bridge.js` 的 `run()` 里，把 `base + '/chat/completions'` 换成你的转发地址。

## 6. 可选增强：加一个极简反代（解决 CORS）

如果服务器能跑 Node，可以加一个 30 行的转发服务，让所有请求走它，CORS 问题就消失了：

```js
// proxy.js   node proxy.js  监听 8888
const http = require('node:http');
http.createServer(async (req, res) => {
  res.setHeader('Access-Control-Allow-Origin', '*');
  res.setHeader('Access-Control-Allow-Headers', '*');
  res.setHeader('Access-Control-Allow-Methods', 'GET,POST,OPTIONS');
  if (req.method === 'OPTIONS') return res.writeHead(204).end();

  const target = decodeURIComponent(req.headers['x-target'] || '');
  if (!target) return res.writeHead(400).end('missing x-target');

  const chunks = [];
  for await (const c of req) chunks.push(c);

  const upstream = await fetch(target, {
    method: req.method,
    headers: {
      Authorization: req.headers.authorization || '',
      'Content-Type': 'application/json',
    },
    body: req.method === 'GET' ? undefined : Buffer.concat(chunks),
  });

  res.writeHead(upstream.status, {
    'Content-Type': upstream.headers.get('content-type') || 'application/json',
  });
  if (upstream.body) {
    for await (const chunk of upstream.body) res.write(chunk);
  }
  res.end();
}).listen(8888);
```

然后在 `web-bridge.js` 的 `run()` / `listModels()` 里，把请求地址改成 `http://你的域名:8888/` 并带上 `x-target` 头即可。

> 注意：这样服务器就会经手用户的 Key，务必自己部署、自己可控。
